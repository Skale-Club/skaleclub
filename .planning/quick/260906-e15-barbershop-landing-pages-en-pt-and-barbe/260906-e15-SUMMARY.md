# Quick Task 260906-e15: Barbershop Landing Pages (EN + PT) + Barbershop Leads Form Summary

Bilingual barbershop landing (`/barbershops` EN, `/barbershops-br` PT) backed by a new unscored 12-question `barbershop-leads` qualification form, seeded idempotently by `scripts/seed-barbershop-landing.ts`.

## What Was Built

### Task 1 — `scripts/seed-barbershop-landing.ts` (325 lines)

Mirrors `scripts/seed-websites-landing.ts` structure exactly: same imports (relative `.js` specifiers, since the `#shared/` alias is not available to standalone `tsx` scripts), same `// ── Section ──` dividers, same `upsertForm()` / `upsertLanding(spec)` helpers (SELECT by slug -> UPDATE if found / INSERT if not, `.returning()` + `console.log`), same `main()` + `main().catch()` handler with `pool.end()`.

**Form `barbershop-leads`** — `isActive: true`, `isDefault: false`, unscored (`maxScore: 0`, all thresholds `0`, every option `points: 0`), 12 questions in order:

| # | id | type | required |
|---|----|------|----------|
| 1 | `nome` | text | yes |
| 2 | `telefone` | phoneCountry | yes |
| 3 | `email` | email | yes |
| 4 | `nomeBarbearia` | text | yes |
| 5 | `numeroCadeiras` | select | yes |
| 6 | `numeroBarbeiros` | select | yes |
| 7 | `sistemaAgendamento` | select | yes |
| 8 | `ticketMedio` | select | yes |
| 9 | `investimentoAnuncios` | select | yes |
| 10 | `principalDesafio` | select | yes |
| 11 | `tipoVisita` | select | yes |
| 12 | `observacoes` | text | no |

All titles, placeholders and option labels are authored in **English** — English is the `t()` source language, so it renders as-is on `/barbershops` and auto-translates on `/barbershops-br`. The known Portuguese-authored `website-leads` form was deliberately not replicated and not modified.

ID-mapping comments document that `nome` / `email` / `telefone` hit native `form_leads` columns, `principalDesafio` also hits the native `form_leads.principal_desafio` column (benign), and the remaining eight ids fall through to `form_leads.customAnswers` (jsonb).

**Xphere hook point:** a block comment above `tipoVisita` records that the question captures the meeting FORMAT only, that Xphere (`C:\Users\Vanildo\Dev\xphere`) owns Calendly-style scheduling, and that no date/time question type exists — so none was invented.

**Landings** — both pages share one `LANDING_SECTIONS` array (`heroWebsites`, `trustBadges`, `processStepper`, `reviews`, `leadFormCta`), differing only in `language` and reciprocal `alternateSlug`. Hero and CTA carry explicit English copy props (unlike the `/websites` seed which falls back to component defaults). No `bgVideoUrl`.

No routing change was needed — the Wouter catch-all `<Route path="/:slug" component={DynamicPage} />` in `client/src/App.tsx` already serves any page slug, and neither slug is reserved.

Ran `npx tsx --env-file=.env scripts/seed-barbershop-landing.ts` against the production Supabase DB (user-approved additive writes).
